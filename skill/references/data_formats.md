# Data Formats Reference Guide

This reference details the file structures supported by the Data Analysis skill, including parsing protocols and handling strategies for common anomalies.

## 1. Comma-Separated Values (CSV)
- **Structure**: Plaintext lines containing values separated by a specific delimiter (comma, semicolon, tab, pipe).
- **Delimiters**:
    - `,` (Standard Comma)
    - `;` (European Standard Semicolon)
    - `\t` (Tab-Separated TSV)
    - `|` (Pipe-Separated)
- **Edge Cases**:
  - **Embedded Newlines**: Fields containing carriage returns or newlines must be enclosed in double quotes.
  - **Quotes inside Quotes**: Escaped double quotes (`""`) are parsed as a single literal quote.
  - **BOM (Byte Order Mark)**: UTF-8 files generated by Excel may contain a BOM header (`\xef\xbb\xbf`) which must be stripped before processing.

## 2. JavaScript Object Notation (JSON & JSON Lines)
- **JSON (Standard)**: A single root array of objects (`[{"col": 1}, {"col": 2}]`) or nested dictionary structure.
- **JSON Lines (ndjson)**: Line-delimited JSON objects where each line is a valid JSON string. Extremely memory efficient for large datasets since it can be read line-by-line.
- **Nested Structures**: Complex sub-documents are flattened using dot-notation (e.g. `user.address.zipcode`) during MongoDB ingestion or Pandas dataframe conversion.

## 3. Apache Parquet
- **Structure**: A binary, columnar file format optimized for fast analytical queries.
- **Header**: Valid Parquet files must start with the magic bytes `PAR1` at the beginning and end with `PAR1`.
- **Advantages**: Preserves column data types, supports dictionary encoding, and leverages compression (Snappy, Gzip) by default.

## 4. Common Anomalies & Solutions
- **Mixed Data Types**: If a column has strings and numbers, pandas will default to an `object` type. Force conversion via `pd.to_numeric(series, errors='coerce')` to parse what is numeric and map the remainder to `NaN`.
- **Date String Formats**: ISO-8601 is preferred. In case of ambiguous formats (e.g., `MM/DD/YYYY` vs `DD/MM/YYYY`), analyze sample ranges or verify with the user.
- **Encoding Failures**: Fallback from `utf-8` to `latin-1` or `cp1252` when parsing documents containing proprietary character codes.
